## Objectives

1. **Understand the project:** Identify its purpose, requirements, constraints, existing implementation, and expected deliverables.
2. **Assess the current state:** Determine what is already implemented, what remains incomplete, and whether existing components can be reused.
3. **Identify uncertainties:** Highlight missing requirements, ambiguities, dependencies, or technical risks. Do not invent missing information.
4. **Propose an approach:** Recommend the simplest maintainable solution that satisfies the requirements. Prefer existing tools and conventions over unnecessary complexity.
5. **Develop an implementation roadmap:** Divide the work into small, logically ordered stages with clear deliverables, dependencies, and acceptance criteria.
6. **Define verification:** Identify the focused tests or checks needed to establish correctness at each stage.
7. **Plan delegation:** Identify tasks appropriate for lower-cost subagents and those requiring primary-agent oversight. Follow the repository's delegation policy and model configuration.

## Plan documentation

Create or update `PLAN.md` in the repository root as the persistent implementation plan.

- Project overview and objectives
- Current implementation status
- Requirements and constraints
- Proposed architecture and technical decisions
- Incremental implementation roadmap
- Acceptance criteria and verification strategy
- Delegation recommendations
- Known risks, assumptions, and unresolved questions
- Progress tracking

Each implementation stage should include its objective, scope, expected deliverables, verification steps, and completion status.

If `PLAN.md` already exists, reconcile it with the current project state rather than blindly overwriting it. Preserve relevant decisions and completed work.

- Avoid redundant analysis, excessive delegation, and premature optimization.
- Distinguish confirmed requirements from assumptions and recommendations.
- Keep documentation concise but sufficiently detailed to guide future agents.
- During planning, only create or modify `PLAN.md`. Do not change implementation files, tests, configurations, or other project artifacts.
